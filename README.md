# محور الأعمال المتكاملة — نظام إدارة المعارض

نظام الإدارة الداخلي لشركة **محور الأعمال المتكاملة لتنظيم المعارض (Axis Integrated Business)**، CR# 1636161، مسقط، سلطنة عُمان. SOVA هو اسم علامة المعارض التي تنظمها الشركة.

**نظام داخلي:** كل الصفحات تتطلب تسجيل دخول موظف، ولا توجد صفحات عامة للزوار.

## ماذا يفعل النظام

| الصفحة | الرابط | الوظيفة |
|---|---|---|
| لوحة التحكم | `/dashboard` | المؤشرات المالية والتشغيلية، إشغال البوثات، آخر العارضين والمدفوعات، والدفعات بانتظار التأكيد |
| تسجيل مشارك | `/register` | استمارة تسجيل المشاركين (البيانات، القطاع، نظام البوث والموقع، الإضافات، السداد، الموافقة على الشروط) وتُصدر **فاتورة ضريبية** PDF فوراً: صفحة الفاتورة وصفحة الشروط والأحكام |
| المعارض والمواعيد | `/exhibitions` | قائمة المعارض مع الإشغال والإيراد المتوقع |
| ملف المعرض | `/exhibitions/:id` | كل تفاصيل المعرض: خارطة المواقع بفئات وأسعار غير محدودة، المشاركون، المصروفات، الرعاة، الإشغال، نقطة التعادل، الصافي، طباعة PDF، تصدير Excel، واستيراد ملف تسجيل المشاركين من Excel |
| العملاء | `/clients` | قاعدة بيانات كل العملاء مع سجل مشاركاتهم، فرز وفلترة (القطاع، المدينة، الحالة، المصدر، المشاركات)، تصدير Excel، ودعوات واتساب |
| طلبات الحجز | `/bookings` | مراجعة طلبات الحجز وقبولها (يُنشأ العارض تلقائياً) أو رفضها |
| العارضون والعقود | `/exhibitors` | قاعدة بيانات العارضين مع البحث والتصفية وطباعة العقد PDF |
| المبيعات والمدفوعات | `/sales` | تسجيل الدفعات، والدخل حسب المعرض وطريقة الدفع، وفاتورة PDF |
| التقارير المالية | `/reports` | تحليل حسب التصنيف وطريقة الدفع وأداء كل معرض، مع تصدير PDF |
| واتساب | `/whatsapp` | رسائل جاهزة (تذكير بالمعرض، تأكيد الحجز، تذكير بالدفع، ترحيب، رسالة مخصصة) لعدة عارضين |

كل المبالغ بالريال العُماني بثلاث خانات عشرية، وضريبة القيمة المضافة 5%.

## قاعدة البيانات

الجداول: `exhibitions`, `exhibitors`, `payments`, `bookings`, `clients`, `exhibition_sites`,
`exhibition_expenses`, `exhibition_sponsors`.

التحديثات على قاعدة البيانات في مجلد `supabase/migrations/`، وتُشغَّل مرة واحدة من
Supabase ← SQL Editor **قبل** نشر نسخة الكود التي تحتاجها:

| الملف | المحتوى |
|---|---|
| `002_clients_and_exhibition_file.sql` | جدول العملاء وربطه بالعارضين، خارطة المواقع، المصروفات، الرعاة، وحقول إضافية للمعرض. إضافة فقط — لا يحذف أي بيانات |
| `003_staff_roles.sql` | صلاحيات الموظفين (مدير / مالية / تسويق) مطبّقة داخل قاعدة البيانات |
| `004_participant_registration.sql` | حقول استمارة التسجيل (الرقم المدني، نوع المنتجات، نظام البوث، الإضافات، الموافقة على الشروط)، وحالة الدفعة «بانتظار التأكيد». يحتاج 003 قبله. إضافة فقط |
| `005_exhibition_tiers.sql` | عدد غير محدود من فئات البوثات التخطيطية لكل معرض (تُنقل الفئات الثلاث القديمة تلقائياً). إضافة فقط |
| `006_exhibition_maps.sql` | إرفاق صورة خارطة لكل معرض: حقل `map_path` ومكان حفظ خاص (`exhibition-maps`) يراه الموظفون فقط، ويرفع فيه المدير والمالية. إضافة فقط |
| `007_marketing_no_amounts.sql` | موظف التسويق لا يقرأ سجل المدفوعات (يسجّل الدفعة من الاستمارة فقط) |

## تسجيل مشارك والفاتورة الضريبية

- الأسعار وفق الاستمارة (قبل الضريبة): ركن مدخل 200، كورنر هاير 150، وسط المعرض 125، صف داخلي 100 ر.ع،
  والإضافات: علاقة 10، طاولة إضافية 5، ستاند للأغراض 10، لوحة خلفية مطبوعة 15 ر.ع. **الضريبة 5% تُضاف فوق السعر.**
  تُعدَّل من `BOOTH_PACKAGES` و `BOOTH_EXTRAS` في `src/lib/constants.js`.
- إذا كان للمعرض خارطة مواقع، يظهر فقط المواقع المتاحة بسعر نظام البوث المختار.
- دفعة يسجلها موظف التسويق تبقى **بانتظار التأكيد** ولا تُحسب في المحصّل، حتى يضغط المدير أو المالية
  «✓ تأكيد الوصول» في صفحة المبيعات. عند اكتمال الدفع يصبح المشارك «مؤكد».
- الرقم الضريبي للشركة يُكتب في `COMPANY.vatNumber` ليظهر على الفاتورة.
- الشروط والأحكام (الصفحة الثانية من الاستمارة) في `PARTICIPATION_TERMS`، وتُطبع في الفاتورة والعقد.

## استيراد ملف المشاركين من Excel

من ملف المعرض ← "استيراد من Excel". يقبل ملف `.xlsx` فيه عمودا **رقم الكشك** و**السعر** على
الأقل، ويقرأ أيضاً: لون الموقع (الفئة)، المبلغ المدفوع، اسم المشارك، الشركة، رقم الهاتف،
نوع النشاط، حالة الدفع، ملاحظات. يعرض معاينة وملاحظات (أرقام مكررة، هواتف ناقصة، خصومات)
قبل التأكيد، ثم ينشئ الخارطة والمشاركين ويربطهم بسجل العملاء ويسجل المبالغ المدفوعة.

## أمور تشغيلية

- **نسخة احتياطية:** التقارير المالية ← "💾 نسخة احتياطية" تنزّل كل البيانات في ملف JSON واحد.
  الخطة المجانية في Supabase لا تحفظ نسخاً احتياطية، فنزّل نسخة أسبوعياً على الأقل.
- **منع التوقف التلقائي:** `.github/workflows/keep-supabase-awake.yml` يرسل طلب قراءة يومياً
  حتى لا يتوقف مشروع Supabase المجاني بسبب عدم الاستخدام.
- **الإرجاعات:** تُسجَّل من المبيعات بنوع دفعة "إرجاع" (مبلغ سالب يُخصم من المدفوع والمحصّل).
- **تحويل مشارك لمعرض آخر:** عدّل المعرض في بيانات العارض، فتتحرر مواقعه في المعرض السابق.
- **إعادة الاستيراد:** استيراد ملف Excel مرة أخرى يحدّث المشاركين الموجودين (بالهاتف أو الاسم)
  ويسجل فقط المبالغ الجديدة — لا تتكرر البيانات.

## التقنيات

- **React 19** و **Vite** و **React Router**
- **Supabase** لقاعدة البيانات وتسجيل الدخول وتحديث عدّاد الطلبات لحظياً
- **jsPDF** و **html2canvas** لملفات PDF، وتُحمَّل فقط عند الطباعة
- **read-excel-file** لقراءة ملفات Excel، وتُحمَّل فقط عند الاستيراد
- **Vitest** للاختبارات و **ESLint** لفحص الكود
- النشر على **Netlify**

## الإعدادات

بيانات الاتصال بـ Supabase موجودة في ملف `.env`:

```
VITE_SUPABASE_URL=...
VITE_SUPABASE_PUBLISHABLE_KEY=...
```

هذه القيم **عامة** بطبيعتها، فالمفتاح المنشور (publishable) مصمم ليعمل داخل المتصفح. حماية
البيانات تتم عبر قواعد **Row Level Security** في Supabase، وليس بإخفاء المفتاح. لا تضع أي
مفتاح سري (مثل `service_role`) في هذا الملف، بل ضع القيم الخاصة في `.env.local`.

## هيكل المشروع

```
src/
  api/          كل عمليات قاعدة البيانات (exhibitions, exhibitors, payments, bookings)
  components/   مكونات الواجهة المشتركة (الأزرار، النوافذ، البطاقات، القائمة الجانبية...)
  context/      تسجيل الدخول والإشعارات المنبثقة
  lib/          الحسابات المالية، التنسيق، رسائل واتساب، ملفات PDF، الثوابت
  pages/        صفحات النظام
  styles/       التصميم (CSS)
supabase/
  schema.sql    وصف الجداول (مرجعي، مستنتج من الكود)
```

البيانات الثابتة كلها في `src/lib/constants.js`: المدن، والتصنيفات، وطرق الدفع، ورقم واتساب
الشركة، ونسبة الضريبة.

## النشر

ملف `netlify.toml` يبني المشروع (`npm run build`) وينشر مجلد `dist`، ويوجّه كل الروابط إلى
التطبيق حتى تعمل روابط مثل `/sales` و `/reports` مباشرة.
